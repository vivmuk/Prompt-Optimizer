# Content loop

## Steps

1. **Pillars (3-5)**: recurring themes where the creator has real evidence of value. One line each + the audience question it answers. No evidence → it's a guess, mark it as one.
2. **Calendar**: dated entries, one per pillar per cadence slot, each with: channel, format, hook (first 6 words), CTA, and asset needs.
3. **Draft channel-native**: the same idea re-expressed per channel's native shape (thread ≠ newsletter ≠ short-video script), never cross-posted verbatim. Lead with the specific, not the thesis.
4. **Visuals**: spec each asset (dimensions, style, text overlay) for generation; images carry the hook, text carries the depth.
5. **Voice check**: one paragraph of the creator's existing voice as few-shot anchor; every draft must pass "would the audience recognize this as them?"
6. **Feedback loop**: define 2-3 metrics per channel that are actually movable (saves/replies over impressions), what threshold triggers a pivot, and where the data comes from. Cycle two must consume cycle one's numbers — build that read step in.
7. **Deliver**: calendar (dated), drafts ready to paste, visual prompts ready to generate, and next cycle's read-and-revise checklist.

## Pitfalls

- Volume kills voice: fewer posts that sound like the creator beat more posts that don't.
- Hooks are the product; the body is the retention. Spend 50% of effort on the first six words.
- Don't schedule 100% capacity — leave 20% slots empty for reactive content, which usually outperforms.
- Metrics that can't change behavior (vanity impressions) don't belong in the loop.
